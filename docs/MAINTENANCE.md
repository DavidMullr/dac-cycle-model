# Maintaining the project

`INSTALL.cmd` creates `model/.venv/` and installs `model/requirements-lock.txt`. Existing local installations are also recognized by the Windows wrappers. Check the active interpreter with `python -B model/run.py env-check`.

Use `START.cmd` and `STOP.cmd` on Windows, or `python -B model/run.py serve` for a portable foreground server. The app binds to this computer only. A source mismatch blocks new runs until the affected changes and checks have been reviewed.

Back up `model/outputs/` if local runs or saved engineering prices matter. These are deliberately absent from release packages. Engineering worksheets are keyed by the saved result's SHA256 and use revision checks to avoid overwriting a newer save.

The current model uses the shared dependencies recorded in `model/config/mof_screening/dependencies.json`. `PREFLIGHT.json` binds the reviewed executable files. After a scientific change, run the relevant numerical checks, review the differences and record the new identity through `screening.mof_screening.preflight.write_preflight`, with the actual check evidence. Regenerate only dependency hashes whose changes have been reviewed.

Rebuild the HTML reports and guides with `python -B tools/render_guides.py` (or `tools/render_reports.cmd` on Windows). This uses Pandoc on PATH or the copy supplied with Quarto. The supplied PDF is generated by `tools/render_report_pdf.py`; it embeds DejaVu Sans from the locked Matplotlib install. The additional PDF dependency is in `tools/requirements-docs.txt`. Inspect rebuilt pages before packaging.

Use [Publishing](PUBLISHING.md) to make a fresh release. Keep development history and obsolete outputs in the separate workspace archive.
